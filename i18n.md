# 🌍 I18N STRATEGY — Toolpika Multi-Language System

## 1. Supported Languages (Initial 10)
`en` (Default), `de`, `fr`, `es`, `pt-BR`, `ru`, `tr`, `it`, `ar` (RTL), `hi`.

## 2. Auto-Detection Logic (Middleware)
1. Check `localStorage` / Cookie for saved preference.
2. If none, check `Accept-Language` header from browser.
3. If unsupported, fallback to `en`.
4. URL structure: `toolpika.site/[locale]/tools/...`

## 3. Translation Engine: Groq API (Llama 3)
We use Groq API for ALL translations. It is free, fast, and context-aware.

### A. UI Strings (Static)
- Stored in `/messages/[locale].json`.
- **Pipeline:** When `en.json` is updated, a script sends new keys to Groq:
  *Prompt:* "Translate the following JSON values to [Target Language]. Keep JSON keys unchanged. Maintain natural UI tone. Return ONLY valid JSON."

### B. Tool Metadata (Dynamic)
- When a tool is added in Admin, a Supabase Edge Function triggers.
- It sends `title` and `description` to Groq for 9 languages.
- Saves to `translations` table.

### C. Blog Articles (Long-form)
- Oracle Cron Job (10 PM) generates English article.
- Script splits article into chunks (max 4000 chars).
- Sends to Groq: "Translate this article section to [Target Language]. Maintain HTML tags, Markdown formatting, and SEO keywords. Do not translate code blocks."
- Publishes localized versions to Supabase.

## 4. SEO & hreflang
- Every page must have `<link rel="alternate" hreflang="..." />` tags in `<head>`.
- Sitemaps generated per locale (`/sitemap-en.xml`, `/sitemap-de.xml`).
- `x-default` hreflang points to English version.

## 5. RTL Support (Arabic)
- If `locale === 'ar'`, add `dir="rtl"` to `<html>`.
- Tailwind uses `rtl:mr-4`, `rtl:ml-0` classes automatically via logical properties.
